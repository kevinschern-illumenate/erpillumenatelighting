# Spec Gen & Webflow Sync: staging and production workflows

One n8n workflow does two jobs for ERPNext:
- **W1** (webhook `Webhook`): generates a template's spec sheet PDF.
- **W2** (webhook `Webhook (ilL-Publish-Job)`): writes a Webflow Product.

Staging is built and tested live in n8n. Every other environment is **built from it** and imported. Nobody edits the production copy by hand.

| File | What it is |
|---|---|
| `spec_sync_staging.json` | The live staging workflow `[STAGING] Spec Gen & Webflow Sync` (`NW0NxiyqKyeVrkOJ`), exported. |
| `spec_sync_environments.json` | The values that differ per environment: ERP origin, webhook paths, brands, credentials. |
| `spec_sync_production.json` | Generated by `tools/build_spec_sync_workflow.py --env production`. Do not edit it by hand. |
| `lib/*.js` | Readable copies of the large Code nodes. CI checks that they equal the nodes in the staging export. |

Plan and runbook: `docs/superpowers/plans/2026-11-23-spec-sync-production-linear-fixtures.md`.

## After a change on staging

1. Make the change in the staging workflow and test it on staging.
2. Export it: in n8n, Download, or use the n8n MCP `get_workflow_details`. Keep `name`, `nodes`, `connections` and `settings`, with nodes sorted by name, and save it over `spec_sync_staging.json`. Copy any changed Code node into its `lib/` file.
3. Rebuild with `python tools/build_spec_sync_workflow.py --env production`.
4. Check with `node tests/portal_unit/spec_sync_workflow.test.cjs`. It fails if any staging value, staging guard or missing node reference reaches production, or if the committed build is stale.
5. Commit the three files together.

## Importing into production

1. In n8n, go to Workflows → Import from file → `spec_sync_production.json`. It arrives **inactive**, named `[PROD] Spec Gen & Webflow Sync`.
2. Bind the webhook secret credential on both webhook nodes. It is left unbound on purpose: the production secret is rotated (`PROD Spec Sync Secret`, header `ILL-Sync-Secret`).
3. These credentials are already bound:
   - ERPNext: `Webflow Marketing API`
   - ilLumenate Webflow writes: `Webflow ilLumenate`
   - template fetch: `Webflow ilLumenate Prod`
4. If the production workflow is already imported, replace its nodes by importing again, or paste the changed nodes. Webhook paths and IDs stay the same, because they are derived from the environment and path.
5. Publish when the runbook says to (step B7).

## What the production build changes

- **ERPNext address:** `https://stagingillumenate.v.frappe.cloud` → `https://app.illumenate.lighting`, everywhere, Code nodes included.
- **Webhook paths:** `staging-product-sync-v2` → `ill-product-sync`, and `staging-generate-spec-sheet` → `ill-generate-spec-sheet`.
- **Staging guards:** the nodes are removed, and the publish path is reconnected.
- **206 Lighting:** not synced in production yet. Its nodes are removed, and the brand switches answer 409 "brand not enabled in this environment". The ERP side also refuses it through `webflow_sync_scope`.
- **Execution data:** nothing is saved for any run, whether successful, failed or manual. n8n stores webhook headers, including the shared secret, in execution data, so a saved failed run would expose the secret to anyone who can open executions.

To enable 206 later, add `lighting_206` to `brands` in `spec_sync_environments.json` once 206's staging question (Q22) is settled. The builder must then also remove the 206 `[staging]` name and slug prefixes from `(206) Transform to Webflow Format`.

## Debugging a production failure

ERPNext keeps what you need first:
- the publish job (`ilL-Publish-Job`): its state, `last_error` and attempts
- the product's Publication History
- the error notification

The spec sheet dialog shows n8n's error answer.

If you need n8n's own run data:
1. In the PROD workflow, go to Settings → "Save failed production executions" → **Save**.
2. Reproduce the failure once.
3. Read the execution.
4. Set the setting back to **Do not save** and delete that execution.
5. **Rotate the secret**: create a new value in the `PROD Spec Sync Secret` credential and the same value in site config `n8n_sync_secret`.

The next rebuild and import also resets the setting to Do not save.

Staging keeps saving failed runs, because it is where you debug. Its secret (`STAGING Sync Secret`) only reaches staging ERPNext.
