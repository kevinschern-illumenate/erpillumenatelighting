Riser Diagram Generator: Implementation Plan
0. Instructions for the implementing agent
You are building a local, browser-based tool (React + Vite, served on localhost). It turns tabular system data into professional lighting-system riser diagrams, with exports to vector PDF and native DXF. The user is an experienced lighting/LED engineer at an architectural LED manufacturer. Do not simplify the domain logic.
Working rules:
	1. Build in the phases below. Stop after each phase with a summary and a demo path so the user can review.
	2. Keep the calc engine pure. src/engine/ is pure TypeScript with no React imports and full unit-test coverage. The UI, the renderer, and both exporters consume engine output; they never recompute electrical values.
	3. Use one drawing model for all outputs. Everything drawn is first produced as a device-independent geometry model in real paper inches. SVG preview, PDF, and DXF are three serializers of that same model. Never draw directly to the DOM or to PDF.
	4. Never invent product data. Seed product libraries with clearly marked EXAMPLE items only. Code tables (NEC resistance, ampacity) live in src/data/ as JSON, with a source field citing table and edition. They must be user-editable.
	5. Use strict TypeScript and Zod everywhere. Zod schemas are the source of truth for data shape and validation. Infer TS types from them.
	6. Verify dependencies before committing to them. Check that each library listed below is maintained and does what's claimed. If one doesn't, propose an alternative before substituting.

6. Engine specification (src/engine/)
6.1 Graph build
Resolve tags into a directed power graph (Source → Equipment → … → Load) and a control graph (ControlLinks plus Equipment.controlFrom). Detect cycles, orphans, and unresolved refs.
Equipment in the same location fed from the same circuit shares one home run. Each additional unit adds a short jumper segment, set by Equipment.feedLengthFt on subsequent units, typically 3–6 ft.
6.2 Load math
	• Tape W: wPerFtMax × lengthFt × (1 + tapeLengthMarginPct).
	• Per-channel current: (W_total / channels) / V, unless maxSimultaneousPct < channels × 100. In that case, PSU load uses W_total × maxSimultaneousPct / (channels × 100), and each channel conductor is still sized for its own max.
	• Pixel tape: pixels × ampsPerPixelMax.
	• Fixtures: watts × qty.
	• PSU output load: Σ connected loads. Error if > 100% of outputs[i].maxW; warn if > psuDeratePct. Warn if a Class 2 output exceeds 100 VA.
	• Decoder: per-channel A vs. maxAPerChannel, and total vs. maxATotal. The decoder's power source is the upstream PSU, so decoder load passes through to that PSU.
	• PSU input current: use maxInputA at the circuit voltage if provided. Otherwise use (connected W / efficiency) / (V × PF). Continuous-load check: Σ input A × continuousLoadFactor ≤ breakerA, plus a warning at breakerLoadLimitPct. Warn when PSU count per breaker exceeds maxUnitsPer20ABreaker (inrush).
6.3 Voltage drop
	• Single-phase / DC: VD = 2 × L × I × R / 1000. Three-phase: √3 × L × I × R / 1000. Use R from the wire entry, falling back to Table 8 by AWG and stranding. If acVdMethod = 'effective-z', use Table 9 effective Z at PF 0.85.
	• Multichannel DC (TW, RGBW): the common V+ conductor carries the sum of the channel currents; each channel return carries its own. Worst-case VD = L × R × (I_common + I_channel_max) / 1000. Support common-conductor doubling as an override: parallel V+ conductors halve R_common.
	• Distributed loads (daisy-chained fixtures, landscape): lumped-at-end uses the full length. distributed uses segment-by-segment summation with interFixtureLengthFt.
	• Tape end-of-run check: V_at_tape = V_out − VD_feed must be ≥ minOperatingV (error), and the feed-wire VD % must be ≤ target (warning). Tape length must be ≤ maxRunFtSingleFeed for end feeds (or maxRunFtDoubleFeed for double-end/center). Otherwise, warn and suggest the minimum number of feeds, and let the user accept the suggestion, which converts the load to multi-feed with N derived feed runs.
6.4 Wire selection algorithm (wireSelect.ts)
For each derived run:
	1. Candidates = wires whose applications include the run type, whose conductor count and roles satisfy what's required (e.g., RGBW = 1 power + 4 channel), and whose environment flags satisfy the run's env. Plenum requires plenum; wet requires wet; direct burial requires directBurial; riser accepts riser or plenum.
	2. Remove failures: 
		○ ampacity (310.16 at terminationTempC for building wire; ampacityA otherwise) < I × continuousLoadFactor;
		○ AWG < minAwgLineVoltage on line-voltage runs;
		○ OCPD rating > the 240.4(D) limit for that conductor;
		○ VD % > target.
	3. Rank: smallest AWG first, then lowest cost if costPerFt exists, then library order.
	4. Terminal check: if the pick's AWG > terminalMaxAwg of either endpoint device, keep it but add warning TERMINAL_OVERSIZE. The message suggests a splice/distribution block with a pigtail, parallel sets, or moving the PSU closer, and quotes the max length for the largest terminal-compatible gauge.
	5. No survivor: error NO_VALID_WIRE, showing the max length achievable with the largest candidate.
	6. Output: RunResult { runId, tag: 'W-##', type, from, to, lengthFt, currentA, voltageV, wireTypeId, parallelSets, vdV, vdPct, endV, checks: {...}, messages[] }.
Data runs (DMX, Ethernet, 0-10V, QS, DALI, SPI) skip VD. They check length and topology instead: DMX ≤ dmxMaxLengthFt and ≤ dmxMaxUnitLoads per segment, else suggest an opto-splitter; Ethernet ≤ 328 ft; SPI ≤ spiMaxDataFt; QS/DALI/0-10V limits come from device specs when present.
Run tags W-## are assigned deterministically: sorted by source → downstream order, stable across edits where possible. Store a tag map so tags don't reshuffle on minor edits.
6.5 DMX
	• Patch validation: startAddress + footprint − 1 ≤ 512; no overlaps within a universe.
	• Auto-patch assigns addresses sequentially by chainOrder, with an optional "start each decoder on a round number" setting.
	• The last device in each wired DMX segment gets a terminator. Warn if the user has flagged it absent.
	• A wireless RX starts a new physical segment.
6.6 Validation codes
Every message has a stable code, severity, entityRef, and human text. Minimum set:
	• Errors: UNRESOLVED_REF, CYCLE, VOLTAGE_MISMATCH, DRIVE_MISMATCH (CV tape on a CC driver and vice versa), PROTOCOL_MISMATCH, INPUT_V_OUT_OF_RANGE, PSU_OVERLOAD, CHANNEL_OVERCURRENT, BREAKER_OVERLOAD, TAPE_UNDERVOLTAGE, NO_VALID_WIRE, DMX_ADDRESS_OVERLAP, DMX_ADDRESS_OVERFLOW.
	• Warnings: PSU_ABOVE_DERATE, CLASS2_OVER_100VA, VD_OVER_TARGET (when overridden), TAPE_RUN_TOO_LONG, TERMINAL_OVERSIZE, DMX_UNIT_LOADS, DMX_LENGTH, DMX_NO_TERMINATOR, SPI_DATA_LENGTH, INRUSH_LIMIT, PHASE_DIMMER_COMPAT_UNKNOWN, EXAMPLE_PRODUCT_IN_USE.
	• Info: MAX_LENGTH_HINT, SUGGEST_SPLIT_FEED.
6.7 BOM
Aggregate equipment and loads by SKU. Tape by feet, and optionally by reel count if the catalog has a reelLengthFt field. Wire by type as Σ run lengths × parallel sets × conductor sets × (1 + wireWastePct). Output to CSV and the on-sheet schedule.

8. Layout engine (src/drawing/layout/)
	1. Power tree via ELK layered (worker), direction: RIGHT (or DOWN for TB): 
		○ elk.edgeRouting: ORTHOGONAL, elk.portConstraints: FIXED_SIDE, elk.partitioning.activate: true.
		○ Partitions fix the columns: 0 Sources, 1 line-voltage switching (relays/dimmers), 2 PSUs/drivers, 3 decoders/pixel controllers, 4 loads.
		○ Spacing is tuned in inches so tags never collide: node-node ≥ 0.375", edge-edge ≥ 0.125".
		○ Node sizes = symbol size + attribute text block.
		○ Identical loads on the same output collapse to one node labelled "(×4)" or with total feet.
	2. Control bus (custom post-pass router): 
		○ Reserve a band above the power tree (left of it for TB flow).
		○ Place control sources (console, gateway, Lutron processor, keypads, wireless TX) in the band.
		○ Route each DMX/QS/0-10V chain as a horizontal bus track with orthogonal drops to each device's N port, in chainOrder. Draw in/out as a loop-through, not a star.
		○ Stack multiple universes/links on offset tracks (0.125"), each labelled at its left end ("DMX U1", "QS LINK 1").
		○ Place the terminator symbol at the chain end. Wireless links are drawn with the WRLS linetype and no bus.
	3. Enclosures: equipment sharing enclosure gets a dashed bounding box with a label. Implement it as ELK compound nodes if partitions still behave; otherwise place enclosure members adjacently via ELK position hints and draw the box post-layout. Test both; choose the more robust.
	4. Pinned nodes: honor layoutOverrides by fixing those positions. Re-route affected edges with ELK interactive mode. If results are poor, integrate libavoid-js for orthogonal connector routing around pinned nodes (Phase 7 stretch).
	5. Pagination: lay out at true plotted size. If the result exceeds the sheet's drawing area, split by panel, then by circuit, then by PSU group. Cross-sheet edges become off-sheet connector pairs ("TO LR-2 / A").
	6. Labels: place each wire tag on the longest horizontal segment of its edge, avoiding overlaps via a simple greedy collision pass. Callout format: W-07 · 2C #12 CL3R · 38' · VD 2.4%, with the text template configurable in settings.
9. Sheet composition (src/drawing/sheet/)
	• Title blocks are JSON templates (titleblocks/*.json) defining the border, the title block region (right vertical strip on ARCH D and ANSI B), and named fields: brand logo, project, number, client, address, sheet title, sheet number, date, scale ("NOT TO SCALE"), drawn/checked, revision table, and stamp.

	• On-sheet content: Legend (symbols and line types actually used), Equipment Schedule, Load Schedule, Wire Schedule (tag, type, from/to, length, current, VD%, qty ft), General Notes, Key Notes.

10. Exporters
10.1 SVG (preview)
Direct mapping of prims. Layers become <g data-layer>. Lineweights map mm to px at the zoom level. The QA overlay renders only here.
10.2 PDF (serializers/pdf/) with AutoCAD PDFIMPORT compatibility
Page and fonts:
	• Page size in points (1 in = 72 pt). Geometry is written at 1:1 so that AutoCAD PDFIMPORT at scale 1 in an inch-unit drawing yields true paper inches.
	• Embed a TrueType font with fontkit, not subset, so the font name stays clean for AutoCAD mapping. Make the font configurable. Default is an OFL metric-compatible Arial alternative (e.g., Arimo) plus a narrow/condensed option.
Text:
	• Each string is written as a single text show operation.
	• No character spacing, no kerning adjustments, no per-glyph positioning.
	• Rotation only 0°/90°.
	• Result: strings import as single TEXT objects, not exploded glyphs.
Geometry:
	• Plain stroked paths only; closed paths for rectangles.
	• No clipping paths, transparency, gradients, shading, or patterns.
	• Solid fills only where needed.
	• Dashed linetypes use PDF dash arrays matching the DXF LTYPE definitions, so AutoCAD's "infer linetypes from dashed segments" option can reconstruct them.
	• Line widths equal the layer lineweight in points.
Layers via Optional Content Groups (build a helper ocg.ts on pdf-lib's low-level API):
	1. Create one OCG dict per layer used (/Type /OCG /Name (E-POWR-WIRE-LV)).
	2. Add /OCProperties << /OCGs [...] /D << /Order [...] /ON [...] >> >> to the catalog.
	3. Add /Properties << /OC0 ref ... >> to each page's resources.
	4. Wrap each layer's content in /OC /OCn BDC … EMC using pushOperators.
Result: PDFIMPORT with "Use PDF layers" recreates the layer structure, and the PDF viewer layer panel shows the same names.
Metadata: title, author, subject (project number), and creator ("ilLumenate Riser Generator vX").
Acceptance test (manual, documented in docs/cad-import-test.md):
	1. In AutoCAD, run PDFIMPORT with: vector geometry on, TrueType text on, "Use PDF layers" on, join line/arc segments on, apply lineweight on, infer linetypes on.
	2. Confirm layers match, text is TEXT objects with correct content and height, lines are lines/polylines, and a known 1.000" reference square in the border measures 1.000".
10.3 DXF (serializers/dxf/)
Format:
	• Target R2000 (AC1015) or newer.
	• Header $INSUNITS = 1 (inches), $MEASUREMENT = 0, $LTSCALE = 1.
	• One DXF per sheet (zipped), plus an optional single-file mode with sheets tiled left to right at 2" gaps.
Tables:
	• LAYER: name, ACI color, linetype, lineweight per layers.json.
	• LTYPE: DASHED, DASHED2, DASHDOT, PHANTOM, HIDDEN, DOT, defined in inches at plot scale.
	• STYLE: the "MAIN" and "BOLD" text styles reference a TTF by file name. Use arial.ttf / arialbd.ttf in the DXF because they're present on any AutoCAD workstation; referencing is not embedding.
Blocks and entities:
	• Each symbol becomes a BLOCK with ATTDEFs. Placements become INSERT + ATTRIB with values. This lets AutoCAD users run Data Extraction on the riser to regenerate schedules.
	• Single-line text uses TEXT with proper alignment points. Notes paragraphs use MTEXT.
	• Polylines use LWPOLYLINE. Solid fills use HATCH SOLID.
Validation:
	• Vitest round-trip: parse with dxf-parser and assert layer set, entity counts, block/attribute presence, and a reference square at 1.000".
	• Manual: open in AutoCAD and in the free ODA viewer.
11. Persistence and import
	• Autosave: the project goes to IndexedDB every change (debounced), with a "recent projects" list. Save/Open uses .riser.json via the File System Access API. Keep a schemaVersion and a migration chain from day one.
	• Libraries: stored in IndexedDB and exported/imported as CSV or JSON.
	• CSV templates: downloadable per category.
	• CSV import flow: upload → auto-map columns by header (fuzzy) → user adjusts mapping → Zod validation with per-row errors → preview diff (new / updated / unchanged by SKU) → commit.
	• Field names: align catalog CSV column names with the user's existing ERPNext item import builder fields (the user will supply the field list), so one export feeds both systems.
12. ERPNext sync (Phase 11; design for it now)
	• Transport: add an optional tiny local proxy (Hono or Express, npm run proxy) because browser-to-Frappe calls will hit CORS. During dev, the Vite server.proxy can serve the same purpose.
	• Auth: token header Authorization: token <api_key>:<api_secret>, stored in a local .env, never in project files.
	• Pull: GET /api/resource/Item with fields and filters (by item group), paginated with limit_start/limit_page_length.
	• Mapping: a JSON mapping file maps ERPNext standard and custom fields to CatalogItem.specs.
	• Sync rules: upsert by erpItemCode. Local overrides are flagged and preserved. Show a sync report (added / updated / conflicts).
	• Direction: pull-only in v1 of this phase. Keep push (e.g., create a Quotation from the BOM) as a future hook.
