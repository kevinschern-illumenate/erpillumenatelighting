# Configurator compatibility register

The v2 changes are implemented locally. Frappe Cloud migration and real user journeys remain release gates.

| Surface | Current adapter | Removal / migration gate |
|---|---|---|
| `/portal/configure` coordinator | `IllConfigurator.Coordinator`, scoped Base lifecycle; retains linear segments, tape runs, neon feeds and reel UI | Keep alongside the wizard while existing URLs are in use. Custom saves use the transaction service below. Reels now use the separate continuous-bulk-stock contract, without cut-assembly cable materials or charges. |
| `mode=wizard` and Desk family partials | Scoped Fixture/TapeNeon/LedSheet classes | Keep mode links. Verify existing configuration reopen and all unsaved-parent behaviors on Cloud. |
| `/configure-tape` and multisegment route | Server redirects to `/portal/configure`, preserving recognized context and selection query parameters | Retain until installed links and external clients are inventoried. No assumption that an unreferenced local route is unused externally. |
| `initWebflowConfigurator`, `validateConfiguration`, `addToSchedule` | Compatibility globals delegate to a default scoped instance | Installed product pages and embeds must be tested before retirement. |
| `portal.configuration.save` | Authenticated POST; normalized family selections, expected schedule revision, stable line key, request key and buyer metadata | Current custom portal callers migrated. Receipt retry validates current permission; a different body cannot reuse the key. Item/BOM/line/receipt creation shares one transaction. |
| `get_schedule_lines_for_configurator` | Existing zero-based `idx`, plus stable `line_key` and schedule `modified` | Old ordinal callers remain supported. V2 saves require the loaded revision, protecting ordinals against reorder races. A pre-migration child name is accepted as a stable fallback. |
| Existing family save APIs | Retained for external clients; new UI uses shared Portal/Desk receipts | Inventory and migrate callers before retirement. Family calculations enforce catalog access and configured rollout controls; public product generation uses a server-only context. Old direct calculation/persistence callers do not gain a schedule/parent retry receipt automatically. |
| `configured_product_builder` | Explicit Linear/Tape/Neon/Sheet dispatch; prospective BOMs use each engine's material manifest | Preserve the old argument shapes. Sheet uses the existing bundle engine rather than falling into neon. |
| Saved-parent legacy Desk apply APIs | Atomic `desk_build_receipt` wrapper | Pass `idempotency_key` and `expected_parent_modified`; concurrent parent edits reject stale writes. Keep keys stable only for an unchanged request. |
| Public Sheet embed | `public_sheet` active choice/preview/PDF API and `[data-ill-sheet-configurator]` loader | See the authoring field register for markup. Owner-approved real masters, CMS bindings, CORS and sign-in handoff require Cloud acceptance. |

Optional site configuration `ill_portal_enabled_families` is a JSON list of canonical family names; omission preserves the existing families, and an empty list disables new family configurations. `ill_portal_pilot_users` is an optional JSON list of user IDs; Sales/Engineering may prepare configurations outside that cohort. Public product-only literature bypasses the user cohort, but still follows family availability. These controls do not grant permissions or hide historical documents. `ill_portal_fixture_groups` additionally gates new group preview/save on the server and defaults off. Read/reuse of already issued historical evidence remains separate from new configuration eligibility.

New calculation in the shared custom forms and coordinator uses preview mode. Save recalculates current approved engineering inputs and creates/reuses the immutable build. Tape/neon preview and persistence now call the same snapshot constructor. A local build identity contains physical scope; an issued offer retains its separate commercial snapshot. New builds pin supported specification/offer/profile/lens/driver engineering PDF sources. Older v2 builds lacking a mapped frozen value return blank and fail a required-value mapping; they are not silently repaired from changed masters.

Local verification: Python service tests use Frappe/database doubles. `tools/check_portal_templates.py` renders five configuration modes into ignored test fixtures. `node --test tests/portal_ui/configurator.test.cjs` exercises those fixtures and shared classes with JSDOM. This does not certify actual Bench permissions, SQL locking, ERP pricing, visual layout or browser behavior.
